# ios/

The native iPhone shell. It hosts the bundled web UI in a WKWebView and owns what the
web can't: keyboard geometry, the Face ID-locked device token, the mark's edit menu,
haptics, lifecycle and media. Spec: [ios-shell.md](../docs/design/ios-shell.md).

- **The page owns the keyboard.** Typing goes to the web's own text boxes, as in phone
  Safari. Native has no text field and no focus controller, and must not take first
  responder from WebKit. `WebShellController.installKeyboardHooks` does only what the
  host can: lets a script's `focus()` raise the keyboard (`AllowFocusPolicy`), hides the
  form accessory bar, and keeps the page's scroll at zero. Native measures the keyboard
  and reports it in `viewport`. A new input feature is web code.
- **Add server is native.** A `muxen://add` link prefills host and optional code but
  never enrols until Next and Add are tapped. Input and failure rules: ios-shell.md,
  "Hosts".
- **The bridge contract has one copy:** the fixtures in
  `MuxenKit/Tests/Fixtures/bridge/`. The Swift DTOs and `web/platform/native/` both
  decode them, so a message change edits all three in one commit.
- **A native request to a daemon is built by `MuxenAppModel.request(on:path:query:)`**,
  which supplies the host's `baseURL`, the path unchanged and the Bearer token, and
  follows redirects only through `HostRequest.redirect`, so a host's token never follows
  a redirect elsewhere. Don't look up a host's URL or token in a new session yourself.
- **AVFoundation never holds a token.** `Media/MediaLoader.swift` builds each fetch with
  `request(on:path:)`, serves only the file asked to play, and forbids reference URLs.
  Don't pass auth headers to an `AVURLAsset`.
- **Every native screen over the page goes up through `MediaController.show`.** It waits
  out a running transition, refuses while another screen is up or the app is locked, and
  lets a lock take it down. A `present` called elsewhere can be dropped by UIKit or stay
  over the lock screen.
- **`project.yml` is the project.** `Muxen.xcodeproj` is generated by XcodeGen and
  ignored; never hand-edit `project.pbxproj`. The signing team stays unset in the repo.
- **Builds and tests run on the Mac:** `ios/scripts/check.sh`. Preflight doesn't build iOS.
- **Installing on the phone:** build Release for the device with the team on the command
  line, then `xcrun devicectl device install app`. The team Xcode is signed into is
  `D4K9ZT557F`; `DQK9XRFMG4` in `security find-identity` is a certificate ID, and using
  it fails with "No Account for Team".

  ```bash
  cd ios && xcodegen generate --spec project.yml
  xcodebuild -project Muxen.xcodeproj -scheme Muxen -configuration Release \
    -destination "id=<phone udid>" -derivedDataPath "$TMPDIR/muxen-ios-device" \
    -allowProvisioningUpdates DEVELOPMENT_TEAM=D4K9ZT557F CODE_SIGN_STYLE=Automatic build
  ```
- **The Simulator can't verify input.** It shows no software keyboard from an agent
  shell, and `simctl` can't tap or type. Keyboard, focus, geometry and rotation are
  verified only by the device checklist in ios-shell.md, which Jimmy runs on his iPhone;
  report a change to any of them as Simulator-built and device-unverified.
